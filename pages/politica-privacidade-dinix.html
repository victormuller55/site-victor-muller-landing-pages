Esta Política vale para o conjunto do produto:

  • o aplicativo Dinix (Flutter, Android e iOS);
  • a API Dinix (https://dinix.api.convertix.net.br, prefixo /api/v1).

O tratamento observa a Lei nº 13.709/2018 (LGPD) e demais normas brasileiras aplicáveis.

Ao criar uma conta no app ou usar a API, você declara ter lido esta Política. O uso do serviço implica o tratamento dos dados necessários para prestá-lo.

2. Como o produto funciona

O app é a interface: cadastro, login, biometria no aparelho, câmera/galeria para foto, cache local e telas de lançamentos.

A API é o servidor: autenticação, banco MySQL, e-mails de verificação, fotos de perfil e todos os dados financeiros da conta.

O app fala com a API em JSON (snake_case em português). Rotas autenticadas usam o cabeçalho autorizacao: Bearer {token}. O identificador do usuário nunca é enviado pelo cliente: a API lê do JWT.

O Dinix não é banco, instituição de pagamento nem Open Finance. Lançamentos são manuais. Não pedimos número completo de cartão, CVV, senha do banco, agência ou conta.

3. Dados tratados na API (servidor)

A API persiste os dados abaixo no MySQL (fuso America/Sao_Paulo). Cada registro pertence à conta autenticada.

3.1 Conta (/api/v1/autenticacao e /api/v1/usuarios)

Dado Como entra Observação
Nome Cadastro e PATCH /usuarios/eu Obrigatório
E-mail Cadastro; login; PUT /usuarios/eu/email após código Identificador de acesso
Senha Cadastro, login, troca e redefinição Só hash BCrypt; nunca em texto
Foto de perfil PUT /usuarios/eu/foto (JPG, PNG ou WEBP, até 5 MB) Opcional; arquivo em disco (/uploads/avatars/)
Código de e-mail (6 dígitos) enviar-codigo-email, esqueci-senha, troca de e-mail Expira em 3 h; reenvio no mínimo a cada 5 min; apagado após o uso
Conta ativa / encerrada POST /usuarios/eu/excluir (exige senha) Ver seção 10
Datas de criação e atualização Sistema Automático

Rotas públicas (sem token): registrar, entrar, enviar/verificar código e redefinir senha. Demais rotas exigem JWT.

A API não pede CPF, RG, telefone, data de nascimento nem documento.

3.2 Dados financeiros na API

Conteúdo que você cria no app e a API grava, isolado por usuário:

Recurso O que é armazenado
Contas Nome, instituição, tipo, saldo inicial, saldo atual, cor
Cartões Apelido, banco, limite, dia de fechamento e vencimento — sem número, validade ou CVV
Faturas Competência, valor, status
Compras Descrição, data/hora, valor, forma de pagamento, categoria, local, notas, parcelas
Itens e produtos Nome, marca, quantidade, preços
Locais Nome, descrição, endereço, cidade, UF, latitude/longitude se você preencher (a API não obtém GPS)
Receitas e receitas recorrentes Descrição, valor, conta, categoria, datas
Despesas recorrentes e assinaturas Nome, valor, vencimento, forma de pagamento, conta ou cartão
Transferências Contas de origem/destino, valor, data, descrição
Investimentos e movimentações Tipo, ticker, quantidade, valores, instituição, notas
Orçamentos, metas, etiquetas, categorias Limites, objetivos, classificação dos gastos
Alertas, calendário, previsão Calculados dos seus lançamentos
Relatórios e patrimônio Agregados mensais/anuais e histórico de saldo/dívida
Anexos Nome, URL e tipo do arquivo vinculado a uma transação
Chaves de idempotência Hash da requisição e resposta, para não duplicar operação

A API gera dashboard, relatórios, estatísticas de locais/produtos e previsão somente com os dados da própria conta.

3.3 Sessão e segurança na API

  • JWT com id da conta e e-mail, validade de 24 horas;
  • API stateless (sem cookie de sessão);
  • em produção: HTTPS; Swagger e /v3/api-docs desligados;
  • foto de perfil servida em GET /uploads/avatars/{arquivo} sem login — quem tiver o link vê a imagem;
  • e-mail transacional (verificação e senha) via SMTP (Hostinger); o servidor pode registrar o endereço no log de envio;
  • cabeçalhos que o app envia (X-Device-Id, X-Platform, X-App-Version, X-Client-Id) não viram ficha cadastral; podem aparecer em log de infraestrutura.

4. Dados tratados no aplicativo (Flutter)

O app coleta na tela, guarda no aparelho o mínimo para funcionar e envia o restante à API.

4.1 O que o app pede a você

  • Nome, e-mail e senha (cadastro e login);
  • código recebido por e-mail;
  • foto (câmera ou galeria), se quiser;
  • todos os lançamentos financeiros das telas do app (contas, cartões, compras, etc.);
  • confirmação da senha para Perfil → Apagar conta.

Não há login com Google, Apple ou Facebook. Não há SDK de analytics, crashlytics, anúncios ou redes sociais.

4.2 O que fica só no aparelho

Dado Onde Observação
Token JWT Cofre do SO (FlutterSecureStorage / Keystore / Keychain) Apagado ao sair ou ao virar o dia
Nome, e-mail, URL da foto Preferências locais Sem a senha
Cache de listagens Preferências (TTL 5 min) Limpo no logout
Cache de referências (contas, categorias…) Preferências (TTL 7 dias) Limpo no logout
Biometria ligada/desligada Preferências Só um interruptor
ID do aparelho Preferências Gerado no app; não é IMEI, IDFA nem Advertising ID

A sessão no app vale só no dia em que você entrou, além do prazo de 24 h do JWT.

4.3 Biometria

Face ID, digital ou PIN do aparelho rodam somente no dispositivo, para desbloquear o Dinix. O app não envia biometria nem template à API. Você pode recusar na primeira vez após o login.

4.4 Permissões do sistema

Permissão Uso no app
Internet / estado da rede Chamar a API
Câmera Foto de perfil (no iOS o texto também menciona comprovantes)
Galeria Escolher foto de perfil
Biometria / Face ID Desbloquear o app, se você ativar
Rede local (iOS) Conectar a serviços na mesma rede, quando aplicável

O app não pede GPS, microfone, contatos, calendário do sistema nem rastreamento publicitário. Latitude/longitude de um local só existem se você digitar no cadastro do local.

4.5 O que o app envia à API

Em toda requisição autenticada o app manda:

  • autorizacao: Bearer {token};
  • versão do app, plataforma (android / ios);
  • ID interno do aparelho;
  • identificadores de cliente (dinix-mobile).

O token contém id da conta e e-mail, gerado pela API.

5. Dados que não coletamos

Nem o app nem a API pedem:

  • CPF, CNPJ, RG, CNH, passaporte;
  • telefone, data de nascimento, gênero;
  • número completo de cartão, CVV, validade, senha de cartão ou banco;
  • agência, número de conta ou chave Pix cadastral (não escreva isso em campo livre);
  • localização contínua / GPS;
  • contatos, SMS, chamadas;
  • dados de redes sociais;
  • identificadores de anúncio (IDFA / GAID).

7. Compartilhamento

Não vendemos dados pessoais.

Podem receber dados, só o necessário:

  1. Você — no app e nas respostas autenticadas da API;
  2. Infraestrutura sob nossa instrução: hospedagem da API, MySQL, disco de fotos, SMTP (Hostinger);
  3. Google Play / Apple — regras das lojas ao distribuir o app;
  4. Autoridades — obrigação legal ou ordem válida.

Uma conta não acessa dados de outra. A API amarra tudo ao usuário do token.

8. Onde os dados ficam e por quanto tempo

Dado Onde Prazo
Conta e lançamentos MySQL (API) Enquanto a conta estiver ativa
Foto de perfil Disco do servidor Até remover, trocar ou encerrar a conta

Hospedagem e SMTP podem usar infraestrutura fora do Brasil, com as salvaguardas da LGPD (art. 33 e seguintes), só para prestar o serviço.

9. Segurança

  • Senha em BCrypt na API;
  • JWT; API sem sessão por cookie;
  • HTTPS em produção;
  • isolamento por usuário autenticado;
  • validação de tipo e tamanho da foto;
  • código de e-mail com prazo e limite de reenvio;
  • biometria opcional só no aparelho;
  • documentação Swagger desligada em produção.

Nenhum sistema é 100% seguro. Use senha exclusiva, não compartilhe o token e, se quiser, ative a biometria no aparelho.

10. Encerrar a conta

No app: Perfil → Apagar conta (confirma a senha).
Na API: POST /api/v1/usuarios/eu/excluir.

O que acontece hoje:

  1. a API desativa o login;
  2. o nome vira “Conta encerrada”;
  3. o e-mail vira um endereço interno anônimo;
  4. a senha é invalidada;
  5. o arquivo da foto é apagado no servidor;
  6. o app limpa token e caches neste aparelho.

Os lançamentos podem permanecer no banco ligados ao id interno já anonimizado. Deixam de estar associados ao seu nome e e-mail civis.

Para apagar de vez os lançamentos, peça pelo canal da seção 1. Avaliaremos no prazo da LGPD, ressalvadas retenções legais.

Sair da conta (logout) não apaga dados na API; só encerra a sessão neste aparelho.

11. Direitos do titular (LGPD, art. 18)

Você pode pedir confirmação, acesso, correção, eliminação, portabilidade (na medida técnica razoável), informação sobre compartilhamentos e revogação do consentimento (foto e biometria).

O Dinix não toma decisão automatizada de crédito, emprego ou efeito jurídico semelhante. Alertas e previsões são contas feitas com os lançamentos que você criou.

Também cabe petição à ANPD. Resposta em regra em até 15 dias, prorrogáveis na forma da lei.

12. Crianças e adolescentes

O Dinix destina-se a pessoas com 18 anos ou mais. Não coletamos dados para oferecer o serviço a crianças. Cadastro de menor de 18 anos pode ser encerrado.

13. Cookies

O aplicativo não usa cookies de publicidade nem pixels.
A API é REST com token no cabeçalho autorizacao; não há login por cookie.

Páginas da Convertix no navegador podem ter cookies do site institucional, descritos na política daquele site.

14. Alterações

Podemos atualizar esta Política quando o app, a API ou a lei mudarem. A data no topo é a versão vigente. Mudanças relevantes poderão ser avisadas no app ou no e-mail cadastrado.
